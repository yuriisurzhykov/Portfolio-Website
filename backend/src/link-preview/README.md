# backend/src/link-preview — smart links

## 2026-10-28 — Превью ссылок (бейдж, строка, карточка)

**Что нужно было сделать.** Ссылки в статьях и кейсах можно показывать как
в Confluence/Jira: бейдж прямо в тексте, компактная строка или полная
карточка с картинкой. Для этого нужны заголовок, описание, картинка и
иконка чужой страницы. Дизайн и решение: макеты «Smart link cards» и
документ «Smart links: техническое решение» (ссылки в PR).

**Как сделано.**

- В контенте хранится только URL и выбор автора. Блок `linkCard`
  (`content/blocks.ts`, `view: "row" | "card"`) и inline-бейдж: обычная
  Markdown-ссылка с title `"smart"` внутри любого текста —
  `[Portfolio-Website](https://github.com/… "smart")`. Это валидный
  CommonMark, поэтому `react-markdown` его уже парсит, а старые рендеры
  просто показывают обычную ссылку.
- Само превью лежит отдельно, в `LinkPreview` (снимок на нормализованный
  URL + язык). Одна и та же ссылка в разных постах и в обеих языковых
  версиях использует один снимок; обновление снимка не трогает контент и не
  создаёт ревизию.
- **В сеть ходит только админка.** `refreshLinkPreviews` вызывается из
  админских роутов (вставка ссылки в редакторе, сохранение черновика).
  Публичная страница вызывает только `getLinkPreviewsForBlocks`: один-два
  индексных запроса, ноль сетевых. Поэтому посетитель не может заставить
  сервер куда-то сходить, а страница не ждёт чужие сайты.
- Ссылки на свои `/work/:slug` и `/journal/:slug` не фетчатся и снимков не
  имеют — читаются из `Work`/`Post` (только PUBLISHED), вместе с обложкой и
  identity hue. Hue только читается, публичный рендер ничего не пишет.

| Файл | Что делает |
| --- | --- |
| `safe-fetch.ts` | единственный сетевой примитив: http(s), порты 80/443, только публичные адреса (проверяются на каждом редиректе), сокет привязан к проверенному IP (DNS rebinding), ≤3 редиректа, 5 с, лимит размера |
| `ip-guard.ts` | какие адреса считаются непубличными (loopback, RFC 1918, link-local с 169.254.169.254, CGNAT, multicast, IPv6-аналоги, `::ffff:` mapped) |
| `extract-metadata.ts` | HTML `<head>` → title/description/siteName/image/favicon; OpenGraph → Twitter → `<title>`; кодировка из заголовка или `<meta charset>` |
| `link-images.ts` | скачивает og:image/favicon, перекодирует sharp'ом (WebP 1200×630 + LQIP, иконка PNG 64×64), кладёт в `MediaStore` как `MediaAsset` (`kind` = `link-image`/`link-favicon`) |
| `collect-urls.ts` | какие URL в документе требуют превью; распознавание своих Work/Post |
| `link-previews.ts` | сервис: `refreshLinkPreviews`, `getLinkPreviews`, `…ForBlocks` |

**Неочевидные решения.**

- `fetch()` не подходит: он сам следует редиректам (нельзя проверить
  адрес каждого шага) и сам резолвит DNS (между проверкой и соединением
  ответ может поменяться). Поэтому `node:http(s)` с собственным `lookup`.
- SVG никогда не растеризуется: librsvg умеет подтягивать внешние ресурсы
  (`<image href="file:///…">`). SVG-иконки пропускаются ещё при разборе
  `<head>`, а любой ответ, похожий на разметку, отклоняется до sharp.
  Покрыто тестом.
- `/favicon.ico` обычно ICO-контейнер, который sharp не читает.
  `pngFromIco` достаёт из него самый большой PNG-кадр; ICO только с BMP
  остаётся без иконки (карточка рисует букву домена).
- Неудачное обновление не затирает прошлый удачный снимок: меняются только
  `status` и `lastError`. Сайт, упавший на день, не превращает карточку
  обратно в голую ссылку. Ошибка видна только в админке
  (`includeErrors`).
- Устаревание: снимок старше 30 дней обновляется при следующем сохранении,
  неудачный повторяется не чаще раза в час (иначе каждый автосейв долбил
  бы лежащий сайт). Отдельного cron нет — для портфолио устаревший
  заголовок чужой статьи не проблема.
- `locale` в `LinkPreview` уже есть, но пишется только `"en"`. Русские
  превью для русской версии поста отложены (решение Юрия от 28.10): это
  будет `Accept-Language: ru` и второй снимок, без миграции ключа.

**Понятность / нагрузка / расширяемость / миграция / SOLID.**
Сетевые правила в одном файле и тестируются на настоящем локальном HTTP
сервере, без моков `fetch`. Нагрузка на публичный путь — один `findMany`
по уникальному индексу на документ. Новый вид (например, отдельная
карточка GitHub из бэклога) — это новый источник данных в
`link-previews.ts`, `LinkPreviewView` не меняется. Миграция только
добавляет таблицу; если её откатить, контент остаётся валидным, а ссылки
просто рисуются обычными. Ответственности разделены: сеть, парсинг,
картинки и хранение — разные модули, сервис только их соединяет.
