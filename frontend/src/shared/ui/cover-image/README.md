# shared/ui/cover-image — CoverImage

## Будет ли переиспользоваться?

Да, с самого начала: `JournalListPage` (маленький тумбнейл в строке
таймлайна), `JournalPreview` (тумбнейл в превью на лендинге) и
`JournalDetailPage` (полноразмерный hero, LCP-элемент детальной страницы)
— три разных размера, один и тот же контракт (`src`/`srcNarrow`/
`placeholder`/`width`/`height`). Одна реализация blur-up + `srcset`, а не
три копии одного и того же `<img>`.

## 2026-08-10 — Первая версия: без `next/image`

**Что нужно сделать.** Показать процедурно сгенерированную обложку поста
(`@portfolio/backend`'s `coverUrlFor`) без просадки CLS/LCP, с плавным
появлением поверх низкокачественного плейсхолдера, пока грузится настоящее
изображение.

**Как сделано.** Обычный `<img>`, не `next/image` — оптимизатор на
1–2-ядерном VPS реально грузит CPU при каждом ресайзе/переэнкоде, а варианты
у нас и так предгенерированы сервером (`backend/src/media/image-processing.ts`
делает 1200px и 640px WebP заранее). Blur-up собран без единой строчки JS:
контейнер получает `background-image: url(placeholder)` (инлайновый base64
data-URI), поверх — непрозрачный `<img>`, который просто перекрывает
плейсхолдер собой в момент отрисовки — никакого `onLoad`-хендлера,
никакого состояния компонента, никакого клиентского бандла ради одной
картинки.

`width`/`height` — обязательные пропы, не опциональные: это ровно то, что
убирает CLS (сдвиг макета) для картинки, чей контейнер иначе не знал бы
своих размеров до полной загрузки. `fetchPriority`/`loading` — пропы, а не
фиксированные внутри компонента: детальная страница передаёт
`fetchPriority="high"`/`loading="eager"` (это LCP-элемент), карточки ниже
сгиба оставляют дефолт (`"auto"`/`"lazy"`).

**Понятность для другого разработчика.** `alt=""` и `role="presentation"`
жёстко зашиты, не пропы — обложка декоративна по построению (случайный
градиент не несёт информации для скринридера), прямая противоположность
`ImageBlock` (`shared/ui/content-blocks`), где `alt` обязателен. Дать
вызывающей стороне возможность передать непустой `alt` означало бы
разрешить ошибку, которую невозможно допустить намеренно.

**Нагрузка.** Ноль клиентского JS сверх обычного decode/paint браузера —
никакого IntersectionObserver, никакого состояния React для отслеживания
загрузки.

**Расширяемость/заменяемость.** `srcNarrow` — необязательный проп:
компонент рендерит одиночный `<img>` без `srcset`/`sizes`, если вызывающая
сторона не передаёт узкий вариант (например, будущий тип медиа с одним
размером). Добавление третьей ширины в `image-processing.ts` — правка
только там плюс новый проп здесь, без переписывания компонента.

**Миграция/отказоустойчивость.** Не применимо — чистый презентационный
компонент, не трогает данные.

**SOLID.** Single Responsibility: компонент не знает, откуда взялись
`src`/`placeholder` (генератор, дедупликация по хэшу, хранилище) — это
работа `coverUrlFor`; он умеет ровно одно — показать уже готовые URL с
правильным blur-up и без сдвига макета.
