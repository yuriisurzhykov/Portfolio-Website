# shared/ui/work-cover-image — WorkCoverImage

## Будет ли переиспользоваться?

Да, с самого начала — три слота нужны сразу: карточка на лендинге
(`SelectedWork.tsx`), новый thumbnail-столбец в ledger (`WorkListPage.tsx`)

правилом приоритета "ручной URL, если задан, иначе сгенерированная
обложка, иначе декоративный плейсхолдер".

## 2026-08-11 — Первая версия, часть Work Item Covers & Unified Identity Hue

**Что нужно было сделать.** У `Work` теперь ДВА источника обложки:
исторический ручной `coverImage`/`heroImage` (просто строка-URL, без
метаданных для blur-up) и новый процедурно сгенерированный
`WorkSummary.cover`/`WorkDetail.cover` (полный `CoverImageData` — src/
srcNarrow/placeholder/width/height). Правило приоритета одинаковое
в трёх разных местах сайта — писать его три раза означало бы три шанса
случайно рассинхронизировать поведение.

**Как сделано.** `override: string | null` — просто ОДНО из двух ручных
полей (`coverImage` для карточки/ledger, `heroImage` для хиро), которое
вызывающая сторона передаёт; сам компонент не знает и не должен знать,
какое поле это было. `override` задан → `PlaceholderCover` с этим `src`
(без blur-up — у ручного URL нет плейсхолдера/размеров). Иначе, если
`cover` задан → настоящий `CoverImage` с blur-up. Иначе → декоративный
плейсхолдер без `src`.

**Понятность для другого разработчика.** Название пропа `override`, не
`coverImage` — специально: этот же компонент используется и для хиро
(`heroImage ?? cover`), где переданное значение НЕ является
`Work.coverImage`. Имя, привязанное к одному конкретному полю схемы,
было бы честным только для одного из трёх вызовов.

**Нагрузка.** Ноль сверх того, что уже стоит `CoverImage`/`PlaceholderCover`
по отдельности — просто выбор одного из двух готовых рендереров.

**Расширяемость/заменяемость.** Появление третьего источника обложки в
будущем (например, AI-сгенерированная альтернатива, фаза 3) — это ещё
один параметр и ещё одна ветка здесь, вызывающим сторонам ничего менять
не придётся.

**Миграция/отказоустойчивость.** Не применимо — чистый презентационный
компонент, ничего не читает из БД и не падает при отсутствии обоих
источников (см. плейсхолдер-ветку).

**SOLID.** Single Responsibility: компонент не знает, ПОЧЕМУ `override`
или `cover` могут быть `null` (ещё не сгенерирована, ещё не добавлена
вручную, и т.д.) — это дело вызывающей стороны; он умеет ровно одно —
выбрать правильный рендерер для того, что реально передано.
