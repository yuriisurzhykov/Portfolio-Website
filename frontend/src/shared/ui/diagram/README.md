# shared/ui/diagram — Diagram

## Будет ли переиспользоваться?

Да — один и тот же `<Diagram>` используется и в публичном рендере
(`ContentBlocks.tsx`), и внутри самого редактора (`DiagramBlock.tsx`, живой
предпросмотр) — админ видит именно то, что опубликуется, не приближение.

## Почему два разных механизма рендера под одним компонентом

`Diagram` — просто свитч по `engine`. Mermaid и PlantUML принципиально
разные: у Mermaid есть настоящий клиентский рендерер (`mermaid.render()`,
чистый JS, без сервера), у PlantUML — нет, ему нужен реальный
PlantUML/Graphviz-бэкенд. Поэтому `MermaidDiagram` рендерит сам, в браузере,
а `PlantUmlDiagram` — просто клиент к `/api/diagrams/plantuml/[encoded]`,
который проксирует на self-hosted `plantuml-server` (см.
`docker-compose.yml`) — диаграмма никогда не уходит на сторонний сервис.

## Почему у Mermaid реальные цвета, а не CSS-переменные

Первая попытка — передать `themeVariables` Mermaid как `var(--color-...)`,
чтобы диаграмма перекрашивалась сама через CSS-каскад при смене темы, без
лишнего рендера. Не сработало: Mermaid прогоняет `themeVariables` через
собственную библиотеку вычисления цвета (для производных оттенков рамок и
т.п.), а она получает ровно ту строку, что дали — `"var(--color-...)"`
буквально, не резолвя её, и падает с "Unsupported color format". Поэтому
`MermaidDiagram` использует настоящие значения из `colors`/`colorsLight`
(`shared/ui/theme/tokens.ts`) и **перерисовывает** диаграмму при смене темы
(`theme` — в зависимостях эффекта), а не полагается на бесплатную
перекраску через CSS.

## DiagramSurface / DiagramLightbox — превью и зум разделены от рендера

`MermaidDiagram`/`PlantUmlDiagram` только производят SVG-строку.
`DiagramSurface` — как это показывается (превью с всегда видимой иконкой
"развернуть" — hover не существует на touch) — и `DiagramLightbox`
(полноэкранный зум/пан через `react-zoom-pan-pinch`, портал в
`document.body` по тем же принципам, что `shared/ui/drawer/README.md`) — обе
части ничего не знают о том, ОТКУДА взялся SVG, поэтому ни один движок
диаграммы не дублирует эту логику.
