# pages/landing — секции JournalPreview и SelectedWork

## 2026-08-06 — TechStack: от текстовых тегов к ряду логотипов + фильтр /work

**Что нужно сделать.** Пользователь хочет ряд монохромных логотипов
технологий вместо текстовых тегов, с accent-подсветкой на hover/pressed, и
чтобы клик по логотипу фильтровал проекты на `/work` по этой технологии.

**Как сделано.** Резолвинг иконки (`resolveTechIcon`,
`shared/lib/tech-icons`) и вычисление `?tech=`-slug'а (`toTechSlug`,
`backend/src/content/tech-slug.ts` — та же функция, что использует
`/work`'s фильтр) переехали в новый `tech-stack-view.ts`,
`buildTechStackView()` — вызывается ОДИН раз в `app/(site)/page.tsx`
(Server Component), а не внутри самой секции (`"use client"`, ради
`useTranslation()`), чтобы `simple-icons` (~3450 иконок) не попал в
клиентский бандл. `TechStack.tsx` теперь получает уже готовый
`TechStackItemView[]` — `{ name, slug, icon: TechIconView, hasProjects }`
— и не знает ни про `simple-icons`, ни про Prisma.

Строка без реально резолвящегося логотипа (`icon.kind === "none"`) молча
пропускается — не рисуется как пустой placeholder. Это осознанное
изменение поведения: раньше секция показывала ВСЕ строки `techStack` как
текстовые теги; теперь это ряд ЛОГОТИПОВ, и дырка на месте лого выглядела
бы как баг, не как "пока не задано". Значит, у части существующих строк
(`"Coroutines & Flow"`, `"KSP"` — нет реального брендового лого) теперь
просто нет отображения на этой секции, хотя сама строка `techStack`
(и её `note`) продолжает существовать и редактироваться в админке —
`note`, авторизуемое в `TechStackSettingsForm`, сейчас этой секцией вообще
не используется (кастомный `Tooltip` показывает только `name` — то, о чём
явно просил пользователь, "hint text с названием технологии", не
описание).

Иконка кликабельна (`next/link` на `/work?tech=<slug>`) только если
`hasProjects: true` — вычисляется через `getPublishedTechSlugs()`
(`backend/src/content/work.ts`), а не просто "есть ли в принципе такая
технология": логотип без единого опубликованного проекта был бы мёртвой
ссылкой на пустой список. Accent hover/pressed/focus — одинаковые классы
для кликабельного и некликабельного варианта (реальная просьба
пользователя была про ВСЕ иконки, не только ссылки).

**Понятность для другого разработчика.** Комментарий у `buildTechStackView`
прямо объясняет, почему "без лого = не рисуем", а не "рисуем пустой бокс"
— без него это легко читалось бы как забытый edge case, а не осознанное
решение.

**Расширяемость/заменяемость.** Если пользователь хочет вернуть текстовые
теги для строк без лого (не решено сейчас, см. план), это один
дополнительный рендер-путь в `TechStack.tsx` для `icon.kind === "none"` —
`buildTechStackView` не нужно трогать, она уже возвращает достаточно
информации (`name`) для любого альтернативного отображения.

**Миграция/отказоустойчивость.** Ни одной Prisma-миграции: `icon` на
`techStack`-строке — новое поле в уже существующем `Json`-столбце
(`SiteContent.data`), с `.default({ type: "auto" })`, так что весь
существующий контент до этой фичи сразу пробует авто-резолв логотипа по
имени, без ручного бэкафилла.

**SOLID.** Interface Segregation: `TechStack.tsx` знает только про
`TechStackItemView` (форма данных), не про то, откуда взялась иконка или
slug — то же разделение, что уже применено ко всем секциям лендинга в
записи от 2026-07-19 ниже.

## 2026-07-19 — Фаза 5: Hero/TechStack/Principles/ContactCta стали пропс-driven

`Hero`, `ContactCta`, `Principles`, `TechStack` (все "use client", читали
статические `@/data/*` напрямую) больше не импортируют данные сами —
каждый принимает свою секцию как проп (`hero`/`contact`/`principles`/
`techStack`, плюс `role`/`email` из `config` для `Hero`/`ContactCta`
конкретно, а не весь `ConfigContent` — Interface Segregation, эти два
компонента используют ровно одно поле конфига каждый). `LandingPage`
получает все 5 значений от `app/(site)/page.tsx` (один `Promise.all` рядом
с уже существующими `getFeaturedWork()`/`getLatestPublishedPost()`) и
раздаёт их секциям — сами секции ничего не знают про `@portfolio/backend`
как источник, только про форму данных (`HeroContent`/`ContactContent`/...).
Подробности схемы/фолбэков — `backend/src/content/README.md`'s Фаза 5.

## 2026-07-18 — `react-router-dom`'s `Link` → `next/link`

Та же механическая замена, что в `journal-list`/`work-list` (`to=` →
`href=`), плюс `"use client"` из-за `useTranslation()`. Остальные секции
лендинга (`Hero`, `Principles`, `TechStack`, `ContactCta`) не используют
react-router и не тронуты в этом шаге.
